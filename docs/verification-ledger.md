## 0.1 狀態值（只用以下九種，不得自創、不得混用）

| 狀態值 | 含義（取得該狀態所需的最低證據） |

| 靜態檢查完成 | 已親自讀程式碼／grep／SHA 比對並記錄行號證據；**僅證明靜態存在或靜態缺失，不證明行為正確** |
| 單元測試完成 | 已實際執行單元測試並留存測試報告計數（XML 的 failures／errors），非引用他人記載 |

> 不得以舊證據升級新版本（版本變更即全部狀態回到「尚未驗證」，除非重新驗證）。

  kotlinc harness `OK (110 tests)`；本帳本**引用該記載、不代為背書、不重跑**。

  且 `.github/workflows/` 絕對不能改（見 `TEST_PLAN.md` §0.2）。在 workflow 更新前，
  CI 永遠不會跑單元測試；CI 通過只證明編譯，不證明測試通過。

  在純 JVM 單元測試中會拋 `RuntimeException("Stub!")`，不在自動化範圍，須走實機驗證

## 0.4 證據欄填寫規則

1. 無證據者填「尚未驗證」，不得留空、不得填「看起來對」「程式碼已寫」。
2. 靜態檢查完成的證據須附檔名＋行號（以目前工作樹為準，見基準文件）；靜態證據
   只支持「存在／不存在」，行狀態仍須註明「行為尚未驗證」。
3. 「未實作」的靜態事實（如 D3-7 dispatch 部分 `onCancelled` 零命中）記為「尚未驗證」，
   不記為「驗證失敗」：驗證失敗只用於已實際執行驗證且失敗的情形。
4. 他人記載（harness 110 項、CI 報告、實機回報）引用時須註明記載來源與「本帳本未複驗」；
   引用不等於背書，不得據此升級狀態。
5. 執行時間欄：尚未執行的填「尚未執行」；已執行的填實際執行日期時間與執行者，不得預填。
