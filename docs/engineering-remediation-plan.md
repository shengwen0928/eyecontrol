> 性質：第一輪分析彙整。**只含分析與文件，未修改任何程式碼**（唯一的寫入是新增 `docs/*.md`）。
> 最高原則：使用安全性優先於功能數量；真實可用性優先於畫面完成；可重現證據優先於程式碼推測；使用者自主控制優先於自動啟動；未驗證必須明示；不得為求待辦全綠而降低驗收標準。

## 0. 目的、原則與證據位階

### 0.1 目的

建立一套能真正完成工程驗證的工作流程：先確認基準與問題、再決定設計、再修正、再以 CI 與實機取得證據，最後才評估發布。本計畫彙整第一輪全部分析結論，列出修正順序與決策清單；**未獲得確認的產品決策，不得擅自實作成正式行為**。

### 0.2 原則

1. 安全性優先於功能數量：任何錯誤手勢、誤觸、意外返回都可能直接影響使用者操作手機的能力。
2. 真實可用性優先於看起來完成：替代操作必須是真正可走通的路徑，不是畫面上有按鈕就算。
3. 可重現證據優先於推測：靜態閱讀、單元測試、CI、實機各有其證據位階，不得互相冒充。
4. 使用者自主控制優先於自動啟動：重啟後不自動恢復眼控工作階段（見 DCL-05）。
5. 未驗證必須明示：門檻、尺寸、編譯、實機行為，凡未量測即標未驗證。
6. 不得降低驗收標準：29 項完成不得宣稱為 Phase 3 通過驗收；CI 通過不得宣稱為發布通過。

### 0.3 狀態詞彙（本計畫唯一合法的狀態語言）

已閱讀 ≠ 已提案 ≠ 已修改程式碼 ≠ 靜態檢查通過 ≠ 單元測試通過 ≠ CI 編譯通過 ≠ 實機測試通過 ≠ 正式發布通過。只有真正取得對應證據才能更新狀態。進度五態：已完成／已實作但尚未驗證／待整合／暫緩等待 D-4／未開始。

## 4. 決策清單（建議 ≠ 決定）

以下每項皆須所有權人確認。建議方案僅為 Agent 建議，**不得把建議當成已獲授權的決定**。成本以小／中／大定性估計，僅供參考。

### DCL-01 — D-4 最終要驗證什麼（§16.1）

- **問題**：D-4 原始目的不明。GAPS 原文只有「校正取消目標的形式？建議：注視角落 2 秒取消；或常駐小取消目標」，沒有 A/B 同時顯示的設計，也沒有實驗目的陳述。
- **現有證據**：逐字引用見 §2.2；六個候選目的（選擇能力／兩種校正條件效果／辨識準確度／流程完成／其他變因／「2 秒」定性）皆未確認，列於 `d4-decision-record.md` Q-D4-01…Q-D4-06。
- **可行方案**：(a) 定義為「取消目標的形式與秒數」（只決形式，不做 A/B 實驗）；(b) 定義為「兩種取消形式的可用性比較」（需另立量測協議）；(c) 廢止 D-4 實驗目的，只保留取消功能需求。
- **優缺點／風險**：(a) 成本最低、無實驗負擔，但若原意是比較則資訊不足；(b) 證據最完整，但需實機量測與額外設計；(c) 最快，但可能丟失原提問意圖。
- **成本**：(a) 小；(b) 中（設計＋量測）；(c) 小。
- **建議方案**：(a)，並把任何比較需求另立為量測任務，不混入 D-4。

### DCL-02 — D-4 最終互動方案（§16.2）

- **問題**：取消目標的形式與秒數未定；舊三選項（角落常駐／確認式兩段／點間取消窗）的前提（同時雙目標可分辨）不成立。
- **現有證據**：新三方案見 `calibration-interaction-redesign.md` §5；硬限制為採樣期無落點預測；取消契約九條見 `CANCEL_CONTRACT.md`。
- **可行方案**：A 非眼控選擇、B 分階段校正測試、C 預設流程加人工覆核（詳見 §2.2）。
- **優缺點／風險**：A 不碰硬限制但採樣中途純眼控使用者無法獨立選擇；B 可比較量測數字但與九點資料流紅線有張力、且不能證明選擇能力；C 改動最小但覆核不能驗證注視正確性、且先存檔後報告的時序不撤銷已存模型。
- **成本**：A 小；B 大（試探模型＋量測）；C 小。
- **建議方案**：A 為預設取消路徑，C 的報告頁覆核併入 D1-8 既有報告頁；B 僅在 DCL-01 選 (b) 時才做。

### DCL-03 — 左右邊緣獨立設定的正式 UI 呈現（§16.3）

- **問題**：開關已實作接線，但正式 UI 呈現（位置、文字、分組、說明）未定；另有粒度張力：實作為左／右分開，GAPS 文字為「側邊捲動開關」單數。
- **現有證據**：5 個 key 與設定頁 5 列開關已驗證接線（C 組）；待決 U-1…U-5 見 `edge-gesture-safety.md`。
- **可行方案**：(a) 維持四邊分開（左／右／頂／底各一）；(b) 側邊合一（左＋右同一開關），頂／底分開。
- **優缺點／風險**：(a) 最彈性，符合不同姿勢與誤觸風險的個別調整；(b) UI 較簡，但左利／右利與不對稱誤觸需求無法分別處理。
- **成本**：(a) 已實作，僅 UI 文字成本小；(b) 中（合併邏輯＋回歸）。
- **建議方案**：(a) 維持分開，UI 呈現以「邊緣手勢」分組、總開關置頂。

### DCL-04 — 50dp 是否成為正式預設值（§16.4）

- **問題**：50dp 在 SM-S9180 上物理寬度約為舊 50px 的數倍，誤觸風險未量測。
- **現有證據**：公式換算表見 `edge-width-device-measurement.md`；真實 DisplayMetrics 待實機讀取；量測協議已備妥。
- **可行方案**：(a) 維持實驗設定，正式預設用 v0.5.9 等效寬度，直到量測完成；(b) 直接定 50dp 為預設。
- **優缺點／風險**：(a) 安全，但需一次量測與一次預設切換；(b) 最快，但誤觸風險未經驗證即進入正式版，違反安全優先原則。
- **成本**：(a) 中（量測＋切換）；(b) 小。
- **建議方案**：(a)。在量測證據出現前，任何宣稱 50dp 為改善的說法皆屬違規。

### DCL-05 — 重啟後是否恢復使用者可見的服務狀態（§16.5）

- **問題**：現況行程重建後有模型即自動恢復追蹤；K-30 要求重啟後不自動執行眼控。

- **可行方案**：(a) 預設採用「恢復設定、不自動恢復眼控工作階段」（§11.3 十步）；(b) 恢復到暫停態（服務在、眼控停、需使用者明確啟動）。
- **優缺點／風險**：(a) 最安全，但使用者每次重啟都需手動啟動；(b) 折衷，但「暫停態」本身須有明確 UI 且不得殘留舊手勢。
- **成本**：(a) 中；(b) 中大。
- **建議方案**：(a)，並以九項重啟測試驗收。
