## 0. 掃描方法與判定標準

### 0.1 掃描範圍與模式

- 範圍：全部使用者可見面——`SettingsActivity` 對話框、主畫面頁尾、
  `res/values/strings.xml`、`README.md`、`docs/privacy.html`、引導文字
  （`SetupWizardActivity`／`WelcomeActivity`，含 layout 預設文字與執行期覆寫文字）、
  設定頁 layout 各列副標；以及程式註解中的隱私主張（`GazeSettings.kt`、
  `CrashReporter.kt`、`EyeImageMetrics.kt`、`VerifyFrames.kt`、`GazeLog.kt` 檔頭）。
- 模式（grep，含變體）：「不上傳」「絕不」「完全不會」「永遠只」「不會傳送」
  「不存照片」「不儲存」「不上載」「只在」「只留」「永不離開」「完全離線」
  「不連網」「不靠雲端」「唯一會連網」「除此之外」。
- 判定標準（以 `privacy-data-flow.md` 的資料流事實為準）：
  - **失實**：在該 flavor／該開關狀態下，與程式行為直接矛盾。
  - **有條件但未加條件**：只在某 flavor 或某開關狀態下成立，文字未加限定，
    讀者會誤解為無條件成立。
  - **基本屬實，須限縮**：核心事實成立，但用詞範圍過寬（例如以「影像」概括全幀與裁切），
    須收窄範圍或補例外。
  - **屬實**：與程式行為一致，且範圍已正確限定。

### 0.2 基線前提（改寫前必須先承認的事實）

1. 側載版首次安裝時，診斷紀錄與遠端監控**預設開啟**
   （`GazeSettings.kt:47-57,185-186`）。任何「預設關閉」敘述皆已過時。
2. 全臉影像不上傳屬實；眼區裁切與診斷數字在側載版預設開啟時會留存並上傳。
   兩者必須分開陳述，不得共用「影像」一詞。
3. 關閉監控開關**不**阻止當下 CSV 檔案上傳（`GazeLog.kt` 的 `pendingUpload` 機制，
   見 `privacy-data-flow.md` §4.2）；「關閉即停止上傳／留存」在 CSV 路徑上不成立。
4. Play 版不上傳，但仍在本機記錄診斷 CSV 與驗證影格；「不上傳」≠「不記錄」。

### 1.1 SettingsActivity 隱私對話框（`SettingsActivity.kt:154-171`）

逐字引用（首句與更新檢查段，換行符為程式字串內的 `\n\n`）：

> 首句：「影像只在手機上即時處理，不儲存、不上傳；校正資料只有數學權重數值，存在手機本機。」
> 側載版更新段：「唯一會連網的功能是「更新檢查」：App 啟動時向 api.github.com 查詢最新 release 版本，不傳送任何個人資料。」
> Play 版更新段：「Play 商店版沒有「更新檢查」連線：更新一律走 Play 商店，本 App 平時不連網。」

- 適用面：設定頁「隱私說明」列點選後彈出；首句兩 flavor 共用，更新段按
  `BuildConfig.SELF_UPDATE_ENABLED` 分支（`SettingsActivity.kt:156-163`）。
- 判定：**失實（側載版）／有條件但未加條件（Play 版）**。
  - 側載版：首句「不儲存、不上傳」與預設開啟的上傳矛盾；「唯一會連網」遺漏 Supabase 上傳

    屬實，但置於「唯一」的前提下，讀者會誤以為 App 只傳送更新檢查請求。
  - Play 版：首句「不儲存」不成立（Play 版仍寫診斷 CSV 與影格，見資料流文件 §3.2）；
    「平時不連網」須限縮為「App 自行發起的連線」（使用者主動點商店列時外部 App 會連網）。
  - 對話框全文未提及診斷／監控（K-12／S-10 殘留），為揭露面最大的缺口之一。
- 改寫要件（不給成品句）：首句必須分 flavor、必須把「全臉影像」與「眼區裁切／診斷數字」
  分開；側載版必須列出第二種連網（監控端點）及其預設開啟狀態；必須說明關閉開關後
  當下檔案的真實語義（見 §0.2 第 3 點）；Play 版必須區分「不記錄」與「不上傳」，
  不得稱「不儲存」。

### 1.3 `strings.xml` 的 `accessibility_desc`（`app/src/main/res/values/strings.xml:3`）

逐字引用：

> 「凝視用視線操作手機：以前鏡頭追蹤眼睛移動游標，凝視停留或眨眼即可點擊。影像只在本機即時處理，不儲存、不上傳；本服務只用來代替手指操作，不讀取、不記錄其他應用程式的內容。」

- 適用面：`accessibility_service_config.xml` 的 `android:description` 引用此字串，
  系統設定頁顯示、使用者授權無障礙服務時的直接依據；**無 flavor 分支**。
- 判定：**失實（前半句）／屬實（後半句，程式行為面）**。
  - 前半句：與 §1.1 首句同一問題，側載版失實，Play 版「不儲存」失實。

    賦予的讀取能力與此句的落差未揭露（K-22／S-01 範圍，屬宣告面缺口，
    不屬本句文字本身的失實）。
- 改寫要件：優先級最高（授權時可見）。前半句改寫要件同 §1.1；後半句可保留，
  但須與前半句的 flavor 限定協調，不得讓讀者以「不讀取畫面」推斷「不傳送任何資料」。
  另見舊稽核要求：此字串優先修正（K-12 修正清單）。

### 2.2 引導文字：WelcomeActivity（layout 預設文字＋執行期覆寫）

layout 預設文字（`activity_welcome.xml:96,205`），Play 版實際顯示者（因覆寫只在側載版執行）：

> 相機卡：「只在手機上即時看眼睛位置，不存照片、不上傳。」
> 隱私卡：「隱私說明：影像與校正資料只留在這支手機，不上傳。更新檢查會連線 GitHub 查詢新版本，除此之外不連網。」

執行期覆寫文字（`WelcomeActivity.kt:28-34`，僅 `REMOTE_MONITOR_ENABLED` 為真時）：

> 相機卡覆寫：「只在手機上即時看眼睛位置，全臉影像不儲存；調校版另會留存與上傳眼區驗證裁切。」
> 隱私卡覆寫：「隱私說明：全臉影像永不儲存、永不離開這支手機；校正資料只留在手機。調校版（GitHub 側載版）另會上傳診斷數字與眼區驗證裁切，正式上架前移除；更新檢查會連線 GitHub 查詢新版本。」

判定：

- **Layout 預設文字：失實（兩 flavor）**。Play 版：「不存照片」不成立（仍存裁切），

- **覆寫文字：基本屬實，兩處須限縮**。(1) 「校正資料只留在手機」：程式不上傳屬實，

  在視覺／語序上不被後句淹沒。
- 改寫要件：layout 預設文字與覆寫文字須同步修正為同一套 flavor 區分邏輯，

**「隱私」一節**（`README.md:180-191`）：

> 首句群：「所有視線推算的影像處理皆在裝置端即時完成：前鏡頭影像僅用於當下的視線推算，
> 不儲存全臉影像；校正資料只有嶺回歸的權重數值…以 `MODE_PRIVATE` 存於本機 SharedPreferences。
> 唯一會連網的功能是「更新檢查」：App 啟動時向 `api.github.com` 查詢最新 release 版本，
> 不傳送任何個人資料；除此之外不含任何第三方追蹤。」
> 例外段：「唯一的例外是內部調校期的「診斷紀錄」與「遠端監控」（僅側載調校版，兩者預設開啟，
> 設定頁可關閉）：診斷數字…與眼區驗證裁切…會記錄在本機並上傳到開發者的調校服務…
> 本機只留最近 3 個時段。此功能…調校完成、上架前…會完全移除。Play 商店版不連網、不上傳。」

判定：**內部矛盾（首句群的「唯一／除此之外」與例外段直接衝突）**。

- 「唯一會連網的功能是更新檢查」在側載版為假（Supabase 為第二種連網），
  即使例外段在下一段補充，「唯一」二字已使首句群失實；讀者只讀首句群即被誤導。
- 「除此之外不含任何第三方追蹤」：追蹤 SDK 面屬實（無第三方追蹤 SDK），
  但置於「唯一會連網」之後，易被誤讀為「除更新檢查外無任何對外傳輸」。
  Supabase 為開發者自有端點、非第三方追蹤 SDK，兩者須在文字上區分，
  不得以「無第三方追蹤」暗示「無對外傳輸」。
- 「Play 商店版不連網、不上傳」：上傳面屬實，記錄面與「不連網」的絕對化須限縮
  （見 §0.2 第 4 點與 §2.1 Play 段）。
- 「本機只留最近 3 個時段」：CSV 面屬實（3 份），影格面屬實（3 時段），
  但「時段」一詞在兩種檔案上的單位不同（CSV 為 120 秒一段、影格為 120 秒一時段），
  合併敘述時須避免讀者誤以為同一機制；另未提 Crash Report 的 5 份留存。
- 改寫要件：刪除「唯一」或將例外段併入同一句群，不得讓「唯一」與例外段分處兩段；
  「第三方追蹤」與「對外傳輸」分開敘述；Play 版區分記錄與上傳；補關閉語義；
  補備份限定。

### 3.2 改寫規則（改寫批次必須遵守，本文件不代寫成品句）

1. **分開陳述**：全臉影像、眼區裁切、診斷數字三者永遠分開寫，不得共用「影像」
   或「資料」一詞概括；每句須指明主語是哪一種。
2. **分 flavor**：側載版與 Play 版的連網／上傳／記錄敘述永遠分開；無 flavor 分支的
   靜態文字（layout、strings）不得保留 flavor 敏感的絕對句，須改為程式分支或
   兩 flavor 皆成立的中性敘述＋指向。
3. **分記錄與上傳**：「記錄在本機」與「上傳到伺服端」為兩個動作，永遠分開寫；
   不得以「不上傳」暗示「不記錄」，不得以「只在本機」暗示「不上傳」。
4. **關閉語義誠實化**：不得再寫「關閉即停止上傳／留存」。必須寫明：關閉後不再開始
   新的記錄／上傳；當下 CSV 檔案仍會在關檔時上傳；已寫入檔案仍在本機；
   丟棄當下檔案的路徑是「清除紀錄」；已上傳資料無 App 內刪除。
5. **預設值誠實化**：側載版必須明說「預設開啟」；不得再寫「預設關閉」。
6. **備份限定**：「只留在這支手機」「解除安裝即完全刪除」等句，必須加備份限定，
   或在同一文件內以備份段落限定其範圍；在排除規則落地前，不得寫成無條件句。
7. **未來承諾加限定**：「上架前整段移除」「調校完成即刪除」必須寫成計畫／承諾，
   不得寫成現況；移除完成前不得宣稱已移除。
8. **不得照抄 §9.5 範例**：§9.5 來源待定位（見文件頭），改寫批次須以本文件的
   資料流事實與改寫要件自行撰寫，不得臆造或抄錄未見來源的範例句。
9. **單一事實來源**：改寫後，`privacy.html` 例外段、README 隱私節、引導 NOTICE 段、
   設定頁對話框、主畫面頁尾、`accessibility_desc` 六面必須逐句對照一致，
   不得一處修正、他處留舊；對照表須留存於改寫批次的審查紀錄，不得只改程式不留紀錄。
