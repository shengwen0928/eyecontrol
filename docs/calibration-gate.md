# 校正有效性檢查（DCL-01 品質門檻）

## 為什麼需要

2026-11-23 使用者實機觀察：全程只看正中間，九點校正也能「通過」。查程式確認：
存檔是無條件的，等級只顯示、不擋存檔；點內離群值剔除只看同一點內的樣本是否
聚集，不檢查眼睛是否跟著目標移動；九點固定順序採樣，時間漂移也可能被模型當成
視線訊號硬湊（25 維特徵、一百多筆樣本， ridge 很容易記住雜訊）。

## 檢查方法

`CalibrationGate.evaluate()`：以虹膜特徵前 4 維（f[0..3]）為準，算九個目標各自
樣本中心的組間分離度，除以組內雜訊（樣本到各自中心的平均距離）。眼睛真的跟著
目標跑時，中心彼此離得遠、各自聚得緊，比值大；全部看中間時中心擠在一起，比值
趨近 1。只用留用進訓練集的樣本（與模型吃的同一批資料）。

門檻 `SEPARATION_RATIO_MIN = 2.0` 為**暫定值**：以第一原理定（真實注視的組間移動
應為注視抖動的數倍；看中間時比值約 1）。必須以校正逐筆紀錄（calib- 上傳，摘要
含 `refused`／`separationRatio`／`separationThreshold`）的真實數據複核、調整；
第一次有真實數據時，先看通過／拒絕的比值分布再定最終門檻，不得憑感覺調。

門檻擋的是「退化資料」，不是「誤差大的真實校正」：留一法誤差再大，只要眼睛真的
跟著目標跑，就放行（誤差由報告頁的等級明說）。眼球活動範圍本來就小的使用者，
若門檻誤擋，以 calib- 數據為據下修門檻，不得直接關掉檢查。

## 拒存流程

檢查在訓練與評估之後、存檔之前執行（`finishCalibrationInternal`）。不通過時：

1. 樣本紀錄照常上傳（`refused=true`，供門檻複核），不因拒存而丟失診斷資料；
2. 不存模型、不清條件歷史（舊模型與舊歷史原樣保留）；
3. 走既有 ERROR 態：明說原因與量到的分離度／門檻，注視可選「重新校正」
   （`recalibrate()`，有舊模型時注視可判讀）或「退出」（舊模型保留）。
   尚無舊模型時，注視選擇無法判讀，畫面明說、可用手指點按或系統返回離開
   （DCL-01：未校正時只能觸控或系統無障礙操作）。

## 測試

`CalibrationGateTest`：九簇分離通過、全看中間不通過、兩組分離通過、單組／空
資料不通過、非有限樣本跳過、雜訊大到比值低於門檻不通過。門檻數值本身不在
測試裡寫死為真理——測試只驗證「比值與門檻的比較邏輯」，門檻的有效性由真實
數據複核（見上）。
