# 校正品質評估方法

本文件說明 EyeControl 如何量測「視線預測準不準」，以及這些數字的意義與限制。
程式實作見 `GazeEvaluator.kt`；校正流程見 `CalibrationActivity.kt`。

## 評估什麼

指標是**平均歐氏誤差**：預測的螢幕座標與目標點之間的直線距離，單位像素（px）。
數字越小越準。誤差以「校正點」為單位彙總：9 個校正點各有約 14 幀樣本
（每點收 20 幀，剔除離群值後保留 70%）。

## 兩種誤差，意義不同

| 誤差 | 怎麼算 | 意義 |
|------|--------|------|
| 訓練集平均誤差 | 模型在自己訓練資料上的殘差 | 偏樂觀。只能當 sanity check：數字異常大代表校正流程或資料出了問題 |
| 留一校正點交叉驗證誤差 | 每次留出一個校正點、用其餘 8 點重新訓練，再預測被留出的點，9 次取平均 | 被評估的點完全沒參與訓練，是對「沒看過的位置預測得準不準」的誠實估計 |

校正完成時顯示的**精度等級以留一法為準**，訓練集誤差只列出來參考。
兩者差距越大，代表模型越依賴死背訓練點、外推能力越弱。

## 精度等級

| 留一法誤差 | 等級 |
|-----------|------|
| < 60 px | 極佳 |
| < 120 px | 優良 |
| < 200 px | 普通 |
| ≥ 200 px | 偏差（建議放穩手機重新校正） |

門檻是開發初期的經驗值，目的是給使用者一個可理解的回饋，不是學術標準。
未來取得更多實機數據後會再校準門檻。

## 逐點誤差

校正完成時會回報誤差最大的校正點（通常是角落點）。用途：

- 使用者可以判斷是不是某個方向特別不準（例如只看左上角時飄移），
  進而調整手機擺放角度或重新校正。
- 開發者可以從多位使用者的逐點分布看出模型的系統性弱點（例如邊緣外推差），
  作為下一輪特徵或模型改進的依據。

## 誠實限制

- 目前的誤差都來自**校正當下的同一段使用過程**：同一支手機、同一姿勢、
  同一光線。換姿勢、換環境後誤差會變大，必須重新校正。
- 交叉驗證用的是同一批校正樣本，不是獨立一天、獨立環境的重測；
  它比訓練集誤差誠實，但仍不是「日常使用準確率」。
- 螢幕尺寸在訓練時直接使用校正頁的實際 view 尺寸傳入，不再用目標座標反推，
  避免尺寸估算誤差混入評估數字。
- 本專案不宣稱任何經過第三方驗證的準確率數字；以上方法與門檻都是
  開發過程中的內部評估工具，公開出來是為了讓改進有據可查。

## 未來要做的評估實驗

1. **特徵消融**：逐組拿掉 22 維特徵中的某一組（轉頭不變性項、交互項、
   二階項、輻輳項），看留一法誤差變化，確認每組特徵真的有用。
2. **跨條件重測**：同一使用者在不同光線、戴眼鏡／不戴眼鏡、手機平放／立起、
   頭部輕微移動等條件下重複校正，記錄誤差分布與漂移。
3. **長時間漂移**：校正後連續使用 10／30 分鐘，量測誤差隨時間的變化，
   判斷是否需要中途重新校正或線上適應。
4. **跨裝置**：不同品牌、不同前鏡頭解析度的手機，確認 1280×720 串流與
   模型在各裝置上的表現是否一致。
5. **使用者試用回饋**：邀請真正需要眼控輔助的使用者試用，記錄任務完成率
   （例如打開 App、點選目標、捲動）與主觀感受，作為功能優先順序的依據。

實驗結果會公開記錄在 repo 中（方法、數據、結論），不只報喜不報憂。
