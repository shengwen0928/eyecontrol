## 0. 摘要

- 目的：建立**可重複執行**的眼控準確度基準：同一條件、同一程序、同一指標定義，
  在不同時間、不同裝置、不同使用者身上重跑，應得到可比對的原始結果與統計摘要。
- 範圍：12 情境（§4）× 4 類指標（§3，共 29 項），全部「尚未驗證」。
- 紅線：**不設通過門檻。** 本次量測只記錄數字；門檻須待基準數字出來、經所有權人定稿後
  才能寫入，不得在本計畫中預設、不得事後為求數據好看而修改測試標準或剔除失敗案例。
- 現況門檻（執行前必須全部滿足，見 §1）：可安裝 APK（CI 產物）、實體裝置、獨立測試目標
  的 ground-truth 紀錄方法、延遲量測的計時方法。**四者目前皆無。**

## 2. 通用規則（適用全部 12 情境）

### 2.1 每次量測 run 必須保存的資訊

每次 run（一次情境 × 一位受測者 × 一台裝置 × 一個模型版本）開始前填寫，缺一即該 run 無效，
不得事後補填：

| 欄位 | 內容 |
|---|---|
| Run ID | `ACC-<情境編號>-<日期>-<序號>`，例如 `ACC-S01-2026-11-24-01`（格式範例，非既有編號） |
| 日期時間 | 開始／結束時間（本地時間＋時區）；裝置時鐘來源註明 |
| App 版本 | 實機安裝的 `versionName`／`versionCode`（現場核對 APK／設定頁，不得抄工作樹數字冒充） |
| Flavor | `sideload`（實機量測一律側載版；Play 版行為差異另行註記，不得混用數據） |
| 裝置 | 型號、Android 版本、螢幕解析度（px）、density／densityDpi／xdpi／ydpi（實機讀取）、螢幕尺寸（英吋，實機讀取或官方規格註明來源） |
| 模型 | 情境 ID（坐姿／躺姿／平放三情境之一）、`calibratedAt`、訓練完成時間、模型版本文字（以 App 顯示為準） |
| 設定 | `dwellTimeMs`、靈敏度、濾波參數、陀螺／臉距／條件修正開關、邊緣手勢開關狀態（逐項抄錄，不得只寫「預設」） |
| 受測者代碼 | 匿名代碼（如 `P01`）；不記錄姓名、照片、全臉影像。眼鏡／隱形眼鏡、是否化妝／反光條件見 §4 各情境 |
| 環境 | 亮度（lux，取 `GazeLog` 的 `lux` 欄或獨立照度計並註明來源）、姿態（pitch／yaw 摘要）、環境描述（室內／室外、光源位置） |
| 執行者／協助者 | 是否單人、雙手是否離開手機、協助者做了什麼（逐項記錄；協助介入的 run 須標註，不得與單人 run 混算） |

### 2.2 原始結果與統計摘要：兩者皆保留

1. **原始結果（raw）**：每一次試驗（trial）的逐筆紀錄（目標位置、預測位置、時間戳、
   臉部 present 與否、是否命中、操作結果），以檔案保存，不得只留平均數。
2. **統計摘要（summary）**：依 §3 定義由原始結果算出，計算方法與排除規則（§2.4）一併記錄；
   摘要須能從原始結果重算，重算不一致即該摘要無效。
3. **檔案命名**：`ACC-<情境編號>-<Run ID>-raw.csv`／`-summary.md`；GazeLog 段落檔名、
   驗證影格 session ID 一併記錄於 run 表（見 §5）。
4. **保存位置**：原始檔案保存於執行紀錄目錄（由執行時決定並記錄路徑）；**不得**把原始結果
   只放在即時通訊訊息、截圖或口頭數字裡。截圖只作驗證證據，不上傳、不入庫
   （`TEST_PLAN.md` §3 通則）。

### 2.3 訓練／測試資料分開（強制）

1. **訓練資料**：九點校正採集的 20 幀／點（`SETTLE_MS = 900`、`SAMPLES_PER_POINT = 20`、
   `KEEP_RATIO = 0.7`，`CalibrationActivity` 現況常數）。訓練集誤差（`GazeEvaluator.evaluate`
   的訓練集誤差）**偏樂觀**（該檔檔頭自述），不得當作準確度基準。
2. **測試資料**：必須與訓練點**位置不同**的獨立測試目標。留一法（leave-one-point-out，
   `GazeEvaluator.leaveOnePointOut`）仍吃同一輪九點採集，只可作輔助參考，**不得**當作
   獨立測試數據；其數值須與獨立測試數值分開列表、分別標註。
3. **獨立測試資料優先**：同一情境同時有獨立測試數據與留一法數據時，基準結論以獨立測試
   數據為準；留一法數據不得覆蓋、不得平均混入獨立測試數據。
4. **模型凍結**：一個 run 內不得重新校正、不得更換模型、不得改設定；中途重新校正即另起
   一個新 run，舊 run 保留原樣（成功或失敗皆保留）。
5. **同一受測者、同一裝置的對照**：v0.5.9 對照量測（見 §4 情境 S09／S10）須同一受測者、
   同一裝置、同一流程，不得以其他裝置／其他使用者的數字作對照（`TEST_PLAN.md` §3.5）。

### 2.4 不挑成功案例、不隱藏失敗測試

1. **全部 run 皆記錄**：成功、中斷、失敗、放棄的 run 一律編號留存；失敗 run 須記錄
   失敗原因與重現步驟，不得刪除、不得以重跑的好結果覆蓋。
2. **不得事後剔除**：任何 trial 的排除須符合 §3 各指標預先寫明的排除規則（如臉遺失幀的
   計法），並在摘要中列出排除筆數與原因；**不得**以「看起來是異常值」為由事後剔除。
3. **中斷即記錄**：臉遺失、相機中斷、App 背景化、裝置過熱等中斷，計入 §3.4 穩定性指標，
   不得把中斷時段靜默剪掉後再算準確度。
4. **不得修改標準**：量測開始後不得更改指標定義、目標尺寸、試驗次數或情境條件以遷就結果；
   如須更改，須另立新版本計畫並註明舊版本作廢原因，舊數據保留、不重算。

### 2.5 受測者與隱私

- 受測者須知悉量測內容與數據用途；診斷紀錄／遠端監控預設開啟的現況（見 §6）須在 run 表
  記錄開關狀態；Play 版無監控、無自更新，不得把側載版數據宣稱為 Play 版數據。
- 不記錄姓名與影像；眼部驗證影格（`VerifyFrames`）只在診斷需要時依現況機制處理，
  不得為本計畫新增影像留存（影像留存另有決定程序，不在本文件授權範圍）。

## 3. 指標定義（全部 29 項，全部「尚未驗證」）

> 單位與分母在執行前不得更改。符號：預測點 `P = (px, py)`（濾波後游標座標，螢幕 px）；
> 目標中心 `T = (tx, ty)`（螢幕 px）；誤差 `e = |P − T|`（歐氏距離，px）。同一 trial 內
> 取「目標呈現後、受測者注視穩定段」的預測點，取點規則見各情境 §4（穩定段定義須在 run 表
> 寫明，不得事後自選最有利的一幀）。
> **通過門檻：無。** 本節只定義「怎麼算」，不定義「多少算通過」。

### 3.1 定位準確度（7 項）

| # | 指標 | 定義（分母／排除規則） | 單位 | 狀態 |
|---|---|---|---|---|
| A1 | MAE（Mean Absolute Error） | 全部有效 trial 的 `e` 之平均。有效 trial＝臉部 present 且有預測點的 trial；臉遺失 trial 不計入 A1，改計入 §3.4 可用度 | px | 尚未驗證 |
| A2 | Median Error（中位誤差） | 全部有效 trial 的 `e` 之中位數。與 A1 同分母；須同時報告 A1 與 A2，不得只報其一 | px | 尚未驗證 |
| A3 | RMSE（Root Mean Square Error） | `sqrt(mean(e²))`，與 A1 同分母 | px | 尚未驗證 |
| A4 | P95 Error | 全部有效 trial 的 `e` 之第 95 百分位數（線性內插法須註明；樣本數不足 20 時註明 P95 不穩定，不得單獨引用） | px | 尚未驗證 |
| A5 | 螢幕像素誤差 | 與 A1 相同數值，但**逐 trial**列出（非平均）：每 trial 的 `e`（px）與目標位置一併保存於原始結果，供按螢幕區域（中央／邊緣／角落）分組統計；分組邊界須在 run 前寫明 | px | 尚未驗證 |
| A6 | 正規化螢幕誤差 | `e / 螢幕對角線長度（px）`，逐 trial 計算後再平均／取中位。螢幕對角線以實機解析度算出並記錄；同時記錄 `e / 螢幕寬度` 作輔助，不得混用兩種分母 | 無單位（比例） | 尚未驗證 |
| A7 | 目標命中率 | 命中 trial 數 ÷ 全部有效 trial 數。命中＝穩定段預測點落在目標矩形／圓形範圍內；目標尺寸（px）與形狀須在 run 前寫明並全程一致，不得中途放大目標遷就命中率 | %（附分子／分母） | 尚未驗證 |

- 報告要求：A1–A4 須附 trial 數 `n`、標準差（A1）與四分位距（A2）；A5 須附分組表；
  A6 須附對角線 px 數；A7 須附目標尺寸。缺少分母的比率一律無效。
- 訓練集誤差與留一法誤差**不得**填入本表；如記錄，須另表並標註「非獨立測試」。

### 3.2 操作可靠性（7 項）

> 操作試驗沿用 `TEST_PLAN.md` §3.2／§3.5 的操作定義：誤觸／漏觸以「意圖」為準，
> 意圖由受測者在試驗前宣告（要點哪個目標／要做哪個手勢），執行者記錄，不得事後推定意圖。

| # | 指標 | 定義（分母／排除規則） | 單位 | 狀態 |
|---|---|---|---|---|
| R1 | 點擊成功率 | 成功點擊 trial 數 ÷ 全部意圖點擊 trial 數。成功＝在一次注視（dwell 滿）內觸發目標動作且無誤觸其他目標 | %（附分子／分母） | 尚未驗證 |
| R2 | 誤觸率 | 非意圖動作次數 ÷ 觀察期間視線進入可觸發區的總次數。觀察期定義見情境（如 2 分鐘自由閱讀，沿用 E-10）；原始次數與比率皆須記錄，不得只報比率 | %（附分子／分母） | 尚未驗證 |
| R3 | 漏觸率 | 未在 2 次注視內完成執行的意圖 trial 數 ÷ 全部意圖 trial 數（沿用 E-10 定義）。每次失敗須記錄原因（臉遺失／dispersion／序列中斷／其他） | %（附分子／分母） | 尚未驗證 |
| R4 | 雙擊辨識正確率 | 正確辨識為雙擊的 trial 數 ÷ 全部意圖雙擊 trial 數；誤判為兩次單擊或無動作皆計失敗。**現況限制**：dispatch 層 `onCancelled` 缺失、雙擊第二下為匿名延遲（見 `engineering-baseline.md` §6.6／§8.1，K-07／K-62），本指標量測前須先確認當時版本的 dispatch 行為並記錄版本，不得以控制器層取消冒充 dispatch 層取消 | %（附分子／分母） | 尚未驗證 |
| R5 | 長按辨識正確率 | 正確辨識為長按的 trial 數 ÷ 全部意圖長按 trial 數；誤判為點擊或無動作皆計失敗 | %（附分子／分母） | 尚未驗證 |
| R6 | 滑動操作成功率 | 成功完成滑動（方向與幅度符合意圖）的 trial 數 ÷ 全部意圖滑動 trial 數；方向錯誤計失敗，不得計成功 | %（附分子／分母） | 尚未驗證 |
| R7 | 邊緣操作成功率 | 成功執行邊緣動作（頂＝返回、底＝首頁、左＝上捲、右＝下捲，現況對應）的 trial 數 ÷ 全部意圖邊緣 trial 數；分邊統計（四邊分開列），不得只報合計。確認階段（頂／底二階段）須分段記錄：進入確認率與確認完成率 | %（附分子／分母，分邊） | 尚未驗證 |

  僅作人工計數的對照，不得單獨作為誤觸／漏觸的證據。
- 門檻未校準的現況（dispersion、連續 present 幀數、方向死區，皆標 `UNCALIBRATED`、

### 3.3 時間效能（6 項延遲）

> **前置條件 P-ACC-2（未滿足）：** 現況程式未見分段延遲計時。以下六項的起訖點先行定義，
> 計時方法（程式內時間戳／外部量測）在執行前須書面決定並記錄方法版本；方法未定前，
> 六項皆不得以 `GazeLog` 的 10 Hz 節流時間戳、樣本新鮮度或主觀秒表感覺冒充。
> `GazeLog` 的 `t` 欄為段內相對毫秒、10 Hz 節流（`MIN_INTERVAL_MS = 100`），
> 只能反映「紀錄間隔」，不能拆分管線各段延遲（見 §6）。

| # | 延遲 | 起點 → 終點（定義） | 單位／統計 | 狀態 |
|---|---|---|---|---|
| L1 | Camera Frame（相機幀延遲） | 相機幀曝光／送入 `ImageAnalysis` → 該幀到達 `FaceTrackerEngine.analyze` 可處理 | ms（中位數＋P90） | 尚未驗證 |
| L2 | Face Landmark（臉部特徵點延遲） | 幀送入 MediaPipe Face Landmarker → 回傳臉部特徵點結果（`GazeSample` 產生前） | ms（中位數＋P90） | 尚未驗證 |
| L3 | Gaze Estimation（視線估計延遲） | 特徵萃取（25 維，含連續光特徵）開始 → `GazeModel.predict` 產出原始預測點 | ms（中位數＋P90） | 尚未驗證 |
| L4 | Cursor Update（游標更新延遲） | 原始預測點 → 經 `OneEuroFilter`／靈敏度／修正偏移後，游標 overlay 位置更新 | ms（中位數＋P90） | 尚未驗證 |
| L5 | Gesture Dispatch（手勢派發延遲） | 判決觸發條件滿足（dwell 滿／邊緣確認完成）→ `dispatchGesture`／`perform*` 發出無障礙手勢請求 | ms（中位數＋P90） | 尚未驗證 |
| L6 | End-to-End（端到端延遲） | 受測者視線到達目標 → 螢幕上可見的動作結果（點擊生效／捲動發生）。L6 含使用者 dwell 時間與系統延遲，須分開記錄「dwell 設定值」與「dwell 外延遲」，不得把 dwell 時間當作系統延遲 | ms（中位數＋P90） | 尚未驗證 |

- 報告要求：每項附樣本數、平均數、中位數、P90、最大值；L1–L5 之和與 L6 的關係
  須註明（L6 另含 dwell 與系統手勢生效時間，不得強求 L1＋…＋L5＝L6）。
- 如計時方法為程式內時間戳，須記錄時鐘來源（`elapsedRealtime`）與取點行號／版本；
  如為外部量測，須記錄設備與方法。兩種方法不得混算。

### 4.1 S01 正常坐姿（基準情境）

- **條件**：坐姿，裝置以常用方式固定（手持或支架，須記錄固定方式與裝置角度）；
  一般室內光（lux 記錄）；無眼鏡或受測者日常配戴狀態（記錄）；臉部距離為受測者自然距離（記錄）。
- **程序**：九點校正（坐姿情境模型）→ 休息／重新擺位 → 獨立測試目標 9 點 × 3 輪
  （每輪目標順序隨機，順序記錄）；每目標呈現後取穩定段預測點。
- **記錄**：§3.1 全部（A1–A7）、§3.2 R1–R3、S-T1／S-T4。S01 為其他情境的**對照基準**：
  其他情境的數字須與同一受測者、同一裝置的 S01 數字並列，不得單獨引用。

### 4.2 S02 躺姿

- **條件**：躺姿（平躺／半躺須記錄）；使用「躺著」情境模型重新校正（不得沿用坐姿模型
  冒充躺姿數據）；裝置角度與臉部相對位置記錄。
- **程序**：同 S01（獨立測試目標 9 點 × 3 輪）。另記錄：由坐姿切換到躺姿時，
  是否出現條件提醒、提醒內容與使用者處置（提醒 preempt 優先序見 `TEST_PLAN.md` G-6）。
- **記錄**：同 S01；另附坐姿→躺姿的模型切換紀錄（切換前後 `active_profile` 與校正時間）。

### 4.3 S03 裝置平放

- **條件**：裝置平放於桌面（與桌面夾角記錄，如用量角／姿態感測器讀數）；受測者俯視；
  使用「平放」情境模型重新校正。
- **程序**：同 S01。另記錄：平放時前鏡頭取景是否完整含雙眼（臉部 present 率見 S-T1）、
  是否需調整裝置位置才能開始（調整次數記錄）。
- **記錄**：同 S01；平放特有的取景／present 問題逐項記錄，不得只報平均誤差。

### 4.4 S04 不同臉部距離

- **條件**：近／中／遠三種距離（建議以臉部到裝置的實測距離分三檔，檔位邊界在 run 前
  寫明並記錄每檔實測值；不得只寫「近／中／遠」）；每檔距離獨立校正（同一情境模型內
  不得混用不同距離的訓練數據冒充單一模型）。
- **程序**：每檔距離：校正 → 獨立測試 9 點 × 2 輪。距離切換時記錄條件提醒與否。
- **記錄**：分檔報告 §3.1 全部；三檔數字並列，不得只報中檔。

### 4.5 S05 不同頭部角度

- **條件**：頭部左右轉、俯仰（角度檔位在 run 前寫明；以 `pitch`／`yaw` 摘要或外部量角
  記錄實測角度）；每檔角度獨立校正。
- **程序**：每檔角度：校正 → 獨立測試 9 點 × 2 輪。另記錄：角度變化時提醒是否跳出、
  提醒後是否需重新校正（以實際行為為準，不得預設結論）。
- **記錄**：分檔報告 §3.1 全部＋S-T1；角度與誤差的對應表逐檔列出。

### 4.6 S06 不同光線

- **條件**：低光（`lux` 低檔）、一般室內光、強光／逆光／側光（光源方向記錄）；
  每種光線條件獨立校正；lux 以 `GazeLog` 的 `lux` 欄或獨立照度計記錄並註明來源。
- **程序**：每種光線：校正 → 獨立測試 9 點 × 2 輪。光線切換時記錄條件提醒與否、
  眼部影像品質（`imgQ`）與反光指標（`glassesHint`）的摘要。
- **記錄**：分光線報告 §3.1 全部＋S-T1；lux 檔位與誤差對應表逐項列出。
  低光下臉遺失增加時，不得把遺失時段剪掉後只報有臉時段的誤差。

### 4.7 S07 眼鏡及反光

- **條件**：同一受測者四種組合（建議）：不戴眼鏡／戴無反光眼鏡／戴一般眼鏡／戴眼鏡＋
  強反光光源；每種組合獨立校正；眼鏡類型與反光條件逐 run 描述。
- **程序**：每種組合：校正 → 獨立測試 9 點 × 2 輪。記錄 `glassesHint`、影像品質與
  臉部 present 率；反光被誤判為瞳孔的疑似事件（如有）逐筆描述，不得以平均數掩蓋。
- **記錄**：分組合報告 §3.1 全部＋S-T1／S-T2；眼鏡／反光條件與誤差對應表。
  **限制**：現況程式以 `EyeImageMetrics` 提供眼部影像度量，是否能區分反光與真瞳孔、
  真抖動與雜訊失真，**尚未驗證**——本情境只記錄現象與數字，不得宣稱系統已能區分。

### 4.8 S08 不同使用者

- **條件**：至少 3 位受測者（建議值；人數在執行前定稿並記錄）；每位獨立校正、獨立 run；
  每位記錄眼鏡狀態、臉部特徵備註（僅與量測相關的客觀描述，如有）、使用經驗（首次／熟練）。
- **程序**：每位：S01 程序一輪（獨立測試 9 點 × 3 輪）。不得共用模型、不得以他人模型
  的數據冒充該受測者的數據。
- **記錄**：分受測者報告 §3.1 全部；跨受測者的平均數須附每位數字，不得只報平均。
  受測者間差異不得以「個別差異」一語帶過：須列出每位的操作可靠性（R1–R3）對照。

### 4.9 S09 不同螢幕尺寸

- **條件**：不同螢幕尺寸的裝置（尺寸、解析度、density 逐台記錄）；每台獨立校正。
- **程序**：每台：S01 程序一輪。邊緣帶幾何（50dp 換算）在每台上以實機 `DisplayMetrics`
  記錄實際 px 數與物理寬度；邊緣操作（R7）分邊記錄。
- **記錄**：分裝置報告 §3.1 全部＋A6（正規化誤差為跨尺寸比較的主指標，px 誤差同時列出，
  不得以 px 誤差直接比較不同尺寸裝置）＋R7。
- **限制**：現況只有 SM-S9180 的量測計畫；其他尺寸裝置**尚未驗證**，本情境在取得裝置前
  不得執行、不得預填數字。50dp 在 SM-S9180 上物理寬度約為 v0.5.9 的 4 倍之說法為引用說法，
  未獨立驗證（見 `engineering-remediation-plan.md` §1.2），本情境須以實機讀數為準。

### 4.10 S10 不同 Android 裝置

- **條件**：不同型號／不同 Android 版本的裝置（型號、Android 版本、相機規格摘要逐台記錄）；
  每台獨立校正；同一受測者優先（排除使用者變因），如換受測者須註明。
- **程序**：每台：S01 程序一輪＋§3.3 延遲量測（如計時方法已定）＋§3.4 S-T6…S-T9。
- **記錄**：分裝置報告 §3.1 全部＋§3.3 全部＋§3.4 全部。跨裝置比較須以同一受測者、
  同一流程為前提，否則只並列、不比較。
- **限制**：同 S09——未取得的裝置不得宣稱已測；模擬器不得代替實機
  （`TEST_PLAN.md` §0.4）。

### 4.11 S11 長時間持續使用

- **條件**：連續使用 30 分鐘與 60 分鐘兩種時長（建議值；時長在 run 前定稿）；
  期間不重新校正、不改設定、不重啟 App（中斷事件如發生，記錄並計入穩定性，不得重開 run 冒充連續）。
- **程序**：開始時九點校正 → 連續任務（自由閱讀＋定時獨立測試目標，每 5 分鐘一組 9 點，
  組次與時間戳記錄）→ 結束時記錄 S-T6…S-T9。
- **記錄**：分窗報告（S-T5）：每 5 分鐘窗的 A1／A2／S-T1／S-T4；全程 S-T2／S-T3；
  記憶體／CPU／電池／溫度（S-T6…S-T9）起訖與峰值。漂移（後窗誤差高於首窗）須明示，
  不得以全程平均掩蓋。
- **限制**：120 秒 CSV 輪轉（見 §6）不得造成時窗切割遺失：run 表須記錄段落檔名清單，
  確認時窗數據完整；缺段即該窗標「數據不完整」，不得以鄰窗數字填補。

### 4.12 S12 追蹤中斷及重新恢復

- **條件**：誘發中斷四種（每種獨立 run）：(a) 臉部離開畫面 2 秒後回來；(b) 臉部離開
  10 秒後回來；(c) 閉眼 2 秒後睜眼；(d) 長時間追蹤中斷（臉部離開 60 秒後回來）。
  中斷期間不得手動干預（不得手點恢復）。
- **程序**：校正 → 穩定注視 10 秒 → 誘發中斷 → 臉部回來 → 記錄恢復過程
  （S-T3）→ 獨立測試 9 點 × 1 輪（驗證恢復後準確度是否回到中斷前水準，與 S01 對照）。
- **記錄**：每次中斷事件：中斷時長、恢復時間（S-T3）、恢復後首窗 A1／A2、是否出現
  舊手勢誤執行（見 `verification-ledger.md` 特殊情境）、是否需重新校正。
  臉遺失期間的 `GazeLog` 行（`face=0`）須保留並計入 S-T1／S-T2，不得刪除。
- **限制**：現況臉遺失時濾波器不重置（基準 §8.1），恢復序列未實作——本情境只記錄
  實際恢復行為，不得宣稱有恢復序列。

## 6. 診斷上傳機制（GazeLog CSV）作為資料來源候選

### 6.1 機制現況（靜態證據，見 `GazeLog.kt`）

- `GazeLog` 記游標數字 CSV 到 App 內部儲存（`gaze-logs/`），遠端監控開啟時關檔後上傳
  至監控端點；診斷／監控預設開啟（`GazeSettings` 預設值皆 `true`，見基準 §7.2）。
- 節流 10 Hz（`MIN_INTERVAL_MS = 100`）、120 秒自動輪轉（`MAX_SECONDS = 120`，關檔後開新段，
  連續紀錄不中斷，最多掉一筆）、舊檔只留最近 3 份（`MAX_FILES = 3`）。
- 摘要（`summarize`）讀最新一份檔案算出，顯示於設定頁對話框；舊版 14 欄檔案以舊位置
  fallback，新檔案一律 17 欄。

### 6.2 17 欄定義（表頭，`GazeLog.kt` 的 `HEADER`）

`t, face, iod, pitch, yaw, rawX, rawY, gainX, gainY, curX, curY, sens, offX, offY, lux, imgQ, glassesHint`

| 欄 | 含義（依程式碼） | 基準用途 |
|---|---|---|
| `t` | 段內相對毫秒（`elapsedRealtime` 差值） | 時序對齊（同段內）；跨段須以檔名時間戳銜接 |
| `face` | 臉部 present 為 1、否為 0 | S-T1／S-T2 的分母依據；`face=0` 的行見 §6.3 |
| `iod` | 特徵索引 6（瞳距相關特徵，程式取 `features[6]`） | 條件記錄（距離相關），非準確度本身 |
| `pitch`／`yaw` | 特徵索引 7／8 | S05 頭部角度的條件記錄 |
| `rawX`／`rawY` | 原始預測點（模型輸出） | 模型輸出幅度分析（輔助）；**無 ground-truth，不得直接當誤差** |
| `gainX`／`gainY` | 增益後預測點 | 增益／靈敏度影響分析（輔助） |
| `curX`／`curY` | 濾波後游標座標 | 預測點 `P` 的候選來源（須與 ground-truth 對齊後才能算誤差） |
| `sens` | 靈敏度 | 設定記錄 |
| `offX`／`offY` | 條件修正偏移 | 見 §6.3（全 0 的既往觀測） |
| `lux` | 環境亮度（非有限值記空欄） | S06 光線條件記錄 |
| `imgQ` | 眼部影像品質／對比（非有限值記空欄） | S06／S07 影像條件記錄 |
| `glassesHint` | 眼區反光比例（非有限值記空欄） | S07 反光條件記錄 |

### 6.3 限制（使用前必須理解，缺一即不得以 CSV 單獨作準）

1. **臉部遺失段**：`face=0` 的行沒有有效的 `rawX`／`rawY`／`curX`／`curY`
   （無臉時無預測，欄位為空）；這些行**不得**計入 A1–A7 的分母、不得以 0 誤差或
   上一幀座標填補；它們計入 S-T1／S-T2。`face` 欄為 0／1 以外的行（如有）須原樣保留並註明。
2. **未校正輸出**：無模型時服務不輸出預測（`onSampleOnMainThread` 在 `model == null` 時返回），
   是否仍有 `GazeLog.record` 行、行內容為何，**須在執行時核對當時版本**，不得假設；
   未校正時段的任何 CSV 行不得計入準確度。校正頁／訓練頁的引擎不走同一紀錄路徑時，
   亦須在 run 表註明紀錄來源。
3. **`offX`／`offY` 全 0 的既往觀測**：既往觀測見 `offX`／`offY` 全為 0 的段落。
   程式上有兩種成因皆會產生 0：條件修正關閉時呼叫端直接傳 `0f`
   （`GazeAccessibilityService` 臉遺失／提醒分支的 `record` 呼叫），以及修正量本身為 0。
   因此全 0 **不等於**「修正未生效」或「數據錯誤」——分析時必須對照 run 表的
   `conditionCorrection` 開關與實際修正量，不得單憑全 0 下結論；開關狀態未記錄的 run，
   其 `offX`／`offY` 不得用於任何修正效果結論。
4. **無 ground-truth**：CSV 只有預測／游標座標，沒有目標位置、沒有 trial 邊界、沒有意圖紀錄。
   單獨的 CSV **算不出** MAE、命中率、誤觸率。必須另有同步的目標／意圖紀錄（同一
   `elapsedRealtime` 時鐘）才能計算；對齊方法與誤差須在 run 表記錄（見 G-ACC-3）。
5. **10 Hz 節流與輪轉**：10 Hz 會漏掉幀間抖動細節（S-T4 須註明取樣率限制）；120 秒輪轉＋
   只留 3 份，長時間 run（S11）須在輪轉前取回段落檔案，否則舊段會被刪除；段落銜接處
   最多掉一筆，須在時序分析時註明。
6. **上傳語義**：關檔時才上傳整份 CSV（`pendingUpload` 期間開關狀態決定是否上傳）；
   撤回／關閉監控是否阻止當下檔案上傳，現況有已知缺口（K-11，`pendingUpload` 未重置，
   見 `privacy-data-flow.md`），量測時須記錄開關操作時間點，不得假設關閉即不上傳。
   伺服端 RLS「僅 INSERT」主張無法由程式碼驗證（基準 §7.2），本計畫不以伺服端數據為唯一保存。
7. **空欄語義**：`lux`／`imgQ`／`glassesHint` 非有限值時記空欄（未知），**絕不以 0 假裝量到**；
   分析時空欄計入「無資料」筆數，不得以 0 參與平均。
